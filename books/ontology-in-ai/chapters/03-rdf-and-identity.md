# 第 03 章　RDF、标识与图数据

本章目标是理解 RDF 的最小结构，并能够解释标识、字面量、空白节点和命名图各承担什么职责。只有这层含义稳定，后续推理和 AI 上下文才有明确对象。

## 3.1 三元组表达一条关系

RDF 1.1 用主语、谓语、宾语组成三元组。主语可以是 IRI 或空白节点，谓语必须是 IRI，宾语可以是 IRI、空白节点或字面量。RDF 图是三元组的集合；集合中重复添加同一条三元组，不会因此记录“发生了两次”。[R01](../references/README.md#r01)

下面是一段可以独立解析的 Turtle：

```turtle
@prefix ex: <https://example.org/maintenance/> .
@prefix d: <https://example.org/data/TENANT-A/asset/> .
@prefix xsd: <http://www.w3.org/2001/XMLSchema#> .

d:P-101 a ex:CentrifugalPump ;
    ex:assetId "P-101" ;
    ex:version 7 ;
    ex:asOf "2026-09-01T09:00:00Z"^^xsd:dateTime .
```

`a` 是 `rdf:type` 的 Turtle 缩写，表示实例的类型。分号沿用同一主语，句点结束一组语句。前缀只是长 IRI 的书写缩写，改变前缀名而保留展开后的 IRI，不会改变标识；改变 IRI 本身则可能改变对象。[R02](../references/README.md#r02)

图中的一条三元组是陈述，不是操作命令。`P-101 usesProcedure PROC-PUMP-01` 表示关联，不能据此认为程序已经执行。维修发生一次，应另建有身份和时间的事件或工单，不能用重复插入这条关联来计数。

## 3.2 标识与名称承担不同职责

`"P-101"` 是字符串；`https://example.org/data/TENANT-A/asset/P-101` 是一个 IRI。前者可以作为资产标签，后者用于连接图中的对象。两个租户都拥有 `P-101` 时，IRI 中的租户范围使它们保持不同的资源标识。

本书的示例域名 `example.org` 用于教学，不代表真实设备服务。IRI 不一定需要在运行时访问网络才能使用。是否可解引用、解引用返回什么、访问时需要何种权限，都属于另外的发布与运行约定。[R01](../references/README.md#r01)

身份设计至少要回答：标识在什么范围内唯一，由谁分配，什么时候可以变更，旧标识如何迁移，外部系统 ID 如何映射。不要把会变化的名称、当前所属部门或模型猜出的描述直接当作长期主键。

在设备迁厂的场景中，设备通常仍是同一台物理设备，所在厂区是会变化的关系。若把厂区名称直接写进不可变身份，迁厂就可能被错误实现为“删除旧设备、创建新设备”。是否包含区域，应根据编号制度和实体生命周期决定；本教程的长期标识只包含租户、实体类别和稳定编号。

## 3.3 字面量必须保留类型、语言和单位

`"92"`、`92` 和 `"92"^^xsd:decimal` 的表达不完全相同。第一个是字符串形式，第二个在 Turtle 中是整数字面量，第三个声明十进制数据类型。解析、比较和校验依赖这些语义，不能只看打印出来的数字像不像。[R01](../references/README.md#r01) [R02](../references/README.md#r02)

语言标签适合区分名称：`"循环泵"@zh` 与 `"circulation pump"@en` 可以共同描述同一设备。它们不会自动变成不同的设备。反过来，名称相同也不保证对象相同。

数值的数据类型不会说明测量单位。即使两个值都使用 `xsd:decimal`，摄氏度和华氏度仍不能直接比较。本教程将源数据 `161.6 F` 转成 `72.00 C`，再将标准化值与单位一起保存。未知温标应触发错误，而不是选择一个看起来合理的解释。

当资料包含“约 90 度”“高于 90 度”或测量区间时，不应一律压成精确数值 90。可以保留上下界、比较关系、不确定性与原始文本。模型抽取时也应尊重这些差别。

## 3.4 空白节点适合局部结构

空白节点表示没有给出全局名称的资源。Turtle 中的 `[]` 常用于表达局部限制或结构，例如一个 SHACL 属性形状。空白节点标签通常只在相应序列化或处理上下文中有意义，不适合作为对外业务 API 的稳定设备 ID。[R01](../references/README.md#r01)

如果一个对象需要被用户收藏、从别的系统引用、反复更新或追溯，就应认真考虑为它分配稳定 IRI。临时图中的一个中间结构则不一定需要全球命名。

还有一个容易忽略的后果：同一 RDF 图可以有不同的合法序列化，空白节点标签也可能不同。因此，“两个 Turtle 文件的 SHA-256 不相同”并不能直接证明图的语义不同。原始文件哈希适合识别文件版本；需要规范化 RDF 数据集时，应采用对应的规范化方案并了解其范围。[R40](../references/README.md#r40)

## 3.5 命名图组织数据，不自动授予权限

RDF 数据集包含默认图以及零个或多个命名图。TriG 可以序列化这种结构。[R01](../references/README.md#r01) [R11](../references/README.md#r11)

```trig
@prefix ex: <https://example.org/maintenance/> .
@prefix g: <https://example.org/graph/> .
@prefix a: <https://example.org/data/TENANT-A/asset/> .
@prefix b: <https://example.org/data/TENANT-B/asset/> .

g:TENANT-A { a:P-101 ex:assetId "P-101" . }
g:TENANT-B { b:P-101 ex:assetId "P-101" . }
```

命名图可以用来组织来源、租户或版本，但图名本身没有访问控制魔法。若查询服务允许用户执行 `GRAPH ?g` 并遍历所有图，数据仍可能全部返回。本教程把可信身份映射到允许的图，并继续检查区域；模型不直接获得任意数据集查询权限。

默认图是否是其他图的联合视图，也不能靠猜。不同数据集构造方式、数据库配置和查询协议可能有不同安排。本教程显式设置 `default_union=False`；面向用户的服务在确定的图上执行参数化查询。

## 3.6 RDF 与 JSON-LD

JSON-LD 通过上下文将 JSON 中的术语映射到 IRI，并表达类型、标识及图结构。普通 JSON 不会因为字段名看起来像业务对象就自动具备同样的 RDF 语义。[R12](../references/README.md#r12)

JSON-LD 适合与 JSON 应用交换图数据，但远程 `@context` 也可能引入网络依赖。解析不可信材料时，需要约束可访问的文件和网络资源。RDFLib 文档明确提醒，远程上下文和 SPARQL 联邦查询可能触发外部访问。[R39](../references/README.md#r39) 本教程的基础导入仅处理仓库内受控文件。
