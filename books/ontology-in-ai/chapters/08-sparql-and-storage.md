# 第 08 章　SPARQL、存储与查询

本章目标是让本体和知识图谱真正服务于查询，同时明确存储产品、查询语义、推理设置和访问控制之间的边界。

## 8.1 从图模式匹配开始

SPARQL 使用图模式描述要匹配的事实。下面的查询寻找设备标识、区域和版本；配套数据图中已经包含类型与子类声明。

```sparql
PREFIX ex: <https://example.org/maintenance/>
PREFIX rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>

SELECT ?asset ?assetId ?region ?version
WHERE {
  ?asset rdf:type/rdfs:subClassOf* ex:Asset ;
         ex:assetId ?assetId ;
         ex:region ?region ;
         ex:version ?version .
}
ORDER BY ?assetId
```

属性路径中的 `/` 表示路径连接，`*` 表示零次或多次。这里显式沿类型和子类关系查询，不等于启用了完整 OWL 推理。其他公理或由不同规则得到的类型，仍要看具体图与推理配置。[R09](../references/README.md#r09)

使用 `SELECT` 获取变量绑定，`ASK` 判断图模式是否存在，`CONSTRUCT` 构造结果图。修改数据则属于 SPARQL Update 等写入接口，应与普通只读查询分别授权。[R10](../references/README.md#r10)

## 8.2 结果数量可能不是对象数量

RDF 图按集合保存三元组，但 SPARQL 查询结果可能具有重复解的多重集语义。一个设备有两种语言标签、三个观测时点，连接查询可能产生多行。若直接 `COUNT(*)`，可能把组合结果误当成设备数。[R09](../references/README.md#r09)

要统计设备，可以根据问题使用 `COUNT(DISTINCT ?asset)`；要取得最新观测，则必须明确时间排序、相同时点冲突以及是否允许无观测。随意加 `DISTINCT` 虽能减少重复行，却不能修复错误的业务连接。

`OPTIONAL` 同样需要理解。把某个过滤条件放在可选模式内部或外部，可能改变缺少值的记录是否被保留。应为“没有观测的设备”准备一条测试，确认查询没有悄悄把它从需要处理的对象中排除。

## 8.3 查询中的不存在具有范围

`FILTER NOT EXISTS` 可以表达在当前查询数据和模式下没有匹配结果。它不自动证明现实世界不存在相应事实。

例如，“没有维修记录的设备”可能仅表示当前获准查询的数据集中没有记录。若用户无权看历史维修图，结果甚至会受到权限范围影响。面向业务人员展示时，应说明数据覆盖和时间范围，不能直接写成“这些设备从未维修”。

这也是开放世界语义与应用查询可以共存的方式：应用可以基于有限数据计算结果，但需要准确解释结果代表什么。

## 8.4 模型调用业务查询，而不是任意端点

在本教程中，面向模型的能力是 `context(principal, asset_id)`。服务从可信身份确定租户和区域，再用固定查询及参数绑定获取观测。模型不提供自己的角色，也不自由选择命名图或远程端点。

RDFLib 支持参数绑定，这有助于将值与查询文本分开。[R18](../references/README.md#r18) 但仅做字符串转义还不够：任意 SPARQL 可以包含远程 `SERVICE`，任意解析输入也可能引入外部访问。还需要固定查询模板、资源预算、输出限制和运行环境控制。[R39](../references/README.md#r39)

高级分析用户可能确实需要自由查询。此时应建立独立的分析环境、访问规则、审计和超时机制，不应把普通智能体工具的权限一起放宽。

## 8.5 存储路线怎样选择

| 路线 | 常见优势 | 需要承担的工作 |
| --- | --- | --- |
| 关系数据库与业务服务 | 事务、约束、现有系统集成成熟 | 显式维护语义映射、关系查询和业务接口 |
| RDF 存储与 SPARQL | RDF 数据交换、图模式与相关语义生态 | 配置推理、索引、事务、访问和运维 |
| 属性图数据库 | 对带属性的节点和关系进行直接建模与遍历 | 明确与 RDF/OWL 概念的映射和差异 |
| 内存 RDFLib | 小型实验、文件处理、原型容易复现 | 容量、并发、持久化和生产治理需另外设计 |
| 统一数据与业务平台 | 共享对象、应用、治理与交付能力 | 采购、平台能力边界、适配与退出迁移 |

属性图和 RDF 都可以表达关系，但数据模型、标识、语言标签、多值、关系属性和推理机制不完全相同。Neo4j 文档对属性图中的节点、关系和属性有明确说明；不能因为画面都是节点与边，就把它当成开箱即用的 OWL 推理器。[R23](../references/README.md#r23)

Jena Fuseki 提供 SPARQL 服务能力，GraphDB 提供相应的存储与推理配置。这些是候选工具的功能定位，不是本书对它们在你的负载下作出的性能排名。[R22](../references/README.md#r22) [R24](../references/README.md#r24)

## 8.6 性能问题先还原工作负载

需要估计的内容包括：显式和派生三元组数量、更新频率、关系分布、常用查询、权限过滤方式、并发和响应目标。平均关系数量很小，但个别节点连接大量对象，可能使某些扩展路径非常昂贵。

对模型工具尤其要限制邻域扩展：允许哪些谓语，最大深度是多少，最多返回多少对象，何时截断并说明结果不完整。本教程沿固定 `partOf` 路径进行有限扩展，每一步都检查范围；它没有向模型开放无限图遍历。

基准测试应包括冷启动、缓存命中、增量更新、推理重算、权限过滤后召回和故障恢复。不要只测一个无过滤、无更新的顺利查询，再把结果用于生产容量承诺。
