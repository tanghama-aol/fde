# 第 10 章　大模型抽取与实体对齐

本章目标是把模型的语言能力用于产生可检查的候选信息，而不是把每次生成都直接变成知识库中的权威事实。

## 10.1 从自由文本到候选陈述

一份维修记录可能写着：“上午巡检时，北厂循环泵显示 92 度，怀疑冷却不良，建议复核。”至少包含四种不同性质的信息：一个观测、模糊的时间、待确认的解释，以及行动建议。

若模型把它抽成“设备故障原因为冷却不良”，就把怀疑升级为事实。正确的抽取合同应保留陈述类别、确定性、原文依据和待补信息。例如，观测可以进入候选观测对象，怀疑进入待验证假设，建议进入提案；它们不应共享一个含糊的 `fact` 状态。

本体提供允许的概念和关系，模型负责从语言中识别可能的内容。二者协作仍然需要实体匹配、单位处理、来源定位和人工或规则审查。

## 10.2 先定义输出合同

一个候选抽取结果至少可以包含：实体候选、关系、值、单位、时间原文、规范化时间、来源文档、原文位置、引用片段、陈述类别和缺失信息。

字段应允许表达不知道。例如，没有给出温标时，`unit` 可以为空并进入补信息流程；不能仅凭“通常用摄氏度”就总是补上。无法唯一定位“循环泵”时，应返回候选或澄清请求。

JSON Schema 可以限定类型、必填字段、枚举、数组数量及条件关系。[R32](../references/README.md#r32) 它不能单独证明值来自原文，也不能证明一个陈述在业务上为真。结构验证、来源检查和语义检查应分开。

本教程对建议输出规定了设备、温度、程序、证据、候选动作和批准要求。模型不能通过附加 `role=admin` 或 `approved=true` 获得权限，因为这些字段既不属于输出合同，也不会被动作服务信任。

## 10.3 实体对齐是一项独立任务

实体对齐要确定一句话中的对象对应哪个已有实体，或是否需要创建新实体。常见依据包括稳定编号、外部系统 ID、名称、型号、地点和时间，但它们的可靠性不同。

建议采用从强依据到弱依据的顺序：先检查获准范围内的稳定标识；再检查经维护的别名；必要时进行相似度候选检索；最后由规则、领域人员或有边界的模型判断。存在多个合理候选时，应保留歧义。

| 情况 | 合理处理 | 不应直接做的事 |
| --- | --- | --- |
| 同编号、不同租户 | 在可信租户范围内定位 | 全局按编号合并 |
| 同名、不同型号 | 保留多个候选并补充条件 | 选相似度最高者作为确定事实 |
| 设备更名 | 更新名称并保留身份和别名 | 自动创建一台新设备 |
| 两个来源确为同一实物 | 记录映射证据与批准过程 | 仅凭名称接近就使用 sameAs |
| 新出现的型号名称 | 进入受控词汇或建模评审 | 让模型任意扩展核心类体系 |

本教程接收显式设备编号，验证的是身份边界和结构化输出，未实现通用自然语言实体链接器。读者扩展别名匹配时，应加入同名、迁厂、更名和跨租户案例。

## 10.4 候选知识进入正式图之前

可以采用三层数据区：原始资料区、候选陈述区和已接受知识区。候选区保存模型版本、提示版本、来源、抽取结果、校验记录和审核状态。未接受的陈述不应被后续问答当成确定事实。

批准进入知识库也不一定意味着永久正确。源文档撤回、设备身份被纠正或事实过期时，需要找到受影响陈述并重新处理。来源关系和版本是支持这种更新的基础。

如果模型建议修改本体本身，例如新增类、改变关系的 domain 或增加等价公理，影响会超过单条记录。此类变更应进入本体评审与回归流程，不能和普通事实抽取共用一个“写入成功”按钮。

## 10.5 给模型足够明确的上下文

提示中说明任务、允许概念、输出结构、失败条件和来源使用规则。提供几个正常与异常例子，尤其是“信息不足”“多个候选”和“原文只是猜测”的情况。

不要把模型内部思考过程作为审计资料。可以要求输出简短理由、引用位置、字段来源和缺失项；这些是用户能核查的解释。模型给自己报出的置信度，需要经过独立校准后才可能用于排序，不能直接代替业务门槛。

结构化输出能力有助于减少格式错误。Ollama 官方文档支持通过 `format` 传入 JSON Schema，也建议在提示中提供相应结构；本书查阅时，文档还注明 Ollama Cloud 不支持结构化输出。[R30](../references/README.md#r30) 因此教程默认面向本地、自备模型环境，仍在客户端重新校验结果。

## 10.6 怎样评估抽取

至少分别检查实体识别、实体对齐、关系正确性、数值单位、时间、来源支持和陈述类别。一个字段完整率很高的系统，仍可能把每条“怀疑”都抽成确定故障。

评估样本应覆盖否定、条件句、修订记录、历史事件、跨页引用和同名实体。近重复文档不能随意分到训练调试集和独立测试集两边，否则结果容易过于乐观。

若输出将影响业务动作，关键字段还应经过服务端检查。例如，本教程把模型报告的温度与授权查询所得值比较，把程序 ID 与设备关系比较，并检查引用是否来自本次证据包。但自由文本摘要中的每一个说法仍需另外评价；这些有限检查不能被报告为完整语义验证。
