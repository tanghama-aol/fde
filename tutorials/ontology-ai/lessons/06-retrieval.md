# 第 06 课　授权检索与程序关系

目标：在同一任务上比较词项重合和关系辅助检索，并验证区域访问边界。对应书籍第 09、13 章。

## 操作

```console
python -m ontology_lab retrieve --asset P-101 --query P-101 --mode lexical --top-k 1
python -m ontology_lab retrieve --asset P-101 --query P-101 --mode graph --top-k 1
python -m ontology_lab retrieve --asset P-201 --query P-201
```

前两条命令的首条文档应分别为 `CATALOG-N-1` 与 `MANUAL-N-1`。第三条返回 `NOT_FOUND_OR_FORBIDDEN`，退出码为 2：北厂身份不能访问南厂 P-201。这里的失败是预期验证结果。

## 解释

资产目录含 P-101 编号，因此词项重合检索优先选它；真正维修程序没有该设备编号。关系模式沿设备 `usesProcedure` 找到 `PROC-PUMP-01`，把相应获准、有效的文档排在前面。

两个模式都检查文档租户、区域和有效期。关系模式没有特殊权限。沿设备上级关系遍历时，也需要逐节点检查范围与深度，避免通过一条链接绕过对象权限。

证据包还包含结构化温度、版本、时点和 `missing_information`。只读到资产目录、没有取得适用程序时，不能把目录当作维修步骤的依据。

本例输入显式资产编号，词项算法不是向量检索；固定程序关系的排序规则也不是通用 GraphRAG 引擎。可以观察具体机制，不能据此比较所有检索产品。

## 常见失败

把 `--top-k` 调得很大可能让两种模式都包含手册，但首位、上下文成本与错误文档仍不同。评价时应固定结果预算。`rdf` 命令能够看到南厂设备，是因为它属于管理员教学演示；不要把它开放成最终用户接口。

## 练习

把查询文本改成程序标题，再比较结果；解释为什么关系增强并非对每条问题都带来改进。设计一条“程序关系过期”的反例，写明需要怎样更新关系、过滤旧文档和测量错误率。
