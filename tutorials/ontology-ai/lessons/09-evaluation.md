# 第 09 课　评估与反例

目标：从原始案例计算指标，并说明结果可以支持哪些结论。对应书籍第 14 章。

## 操作

```console
python -m ontology_lab evaluate --output .runs/evaluation.json
python -m unittest discover -s tests -v
```

第一条输出四个检索案例和两个防护案例；第二条运行本版 40 项行为测试。HTTP 适配器测试会启动只在回环地址监听的临时测试服务，结束后关闭，不调用真实模型。

## 预期结果

| 检查 | 本版实测 |
| --- | --- |
| 词项检索 Hit@1 | 2 / 4 = 0.5 |
| 程序关系辅助 Hit@1 | 4 / 4 = 1.0 |
| 区域越权案例 | NOT_FOUND_OR_FORBIDDEN |
| 过期数据案例 | needs_information |
| 真实模型调用 | 0 |
| 生产业务系统调用 | 0 |

查看[evaluation-cases.json](../data/evaluation-cases.json)，逐条对照 `expected_document` 与实际返回列表。报告中的 `cases` 是检索案例分母，不应把两个防护案例加入这个分母。

## 解释

四个检索案例是人工设计的机制实验；两个方法都得到显式资产编号。结果不评价实体链接、向量检索、模型事实正确率或生产延迟，也不是独立抽样基准。

40 项测试覆盖具体契约，例如 domain 推断、跨租户身份、错误字段、缺失观测、批准过期、条件版本变化、外部响应丢失及回执不匹配。测试名称和断言是行为说明，不能当作真实用户规模或防御覆盖率。

报告保存 Python、依赖版本和实现摘要。修改实现后，旧结果不能继续冒充新版本实测。固定业务时钟用于复现，`executed_at` 用于记录实际执行时点。

## 常见失败

把 `hit_at_1: 1.0` 说成“大模型准确率 100%”混淆了任务、样本和系统组件。删除难例后总分升高也不能证明改进。调参时使用过的案例应标为开发集，另准备独立评估集。

## 练习

给评估集设计四条新场景：关系缺失、关系过期、名称歧义、程序被撤回。分别说明正确答案、应拒答条件和需要改变的组件。先写标签再调算法，避免按现有结果反向定义成功。
