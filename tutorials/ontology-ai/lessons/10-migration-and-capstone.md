# 第 10 课　迁移与综合项目

目标：完成一次可重复迁移，运行完整工作流，并形成自己的交付说明。对应书籍第 16—18 章。

## 迁移操作

```console
python -m ontology_lab migrate --workdir .runs/migration-lesson
```

查看[migration-v1.ttl](../data/migration-v1.ttl)与[更新语句](../queries/migrate-v1-v2.ru)。首次 `moved_edges` 为 1，再次为 0，旧关系剩余为 0。输出图保存为 `migrated.ttl`。

示例把 `legacyAsset` 改成 `forAsset`，并把旧谓词标为弃用。文件名的 v1/v2 是迁移前后样例名称；本体版本由样例的 `0.9.0` 更新为本教程基线 `1.0.0`，不是声称发布了领域本体 2.0。

这里每次命令从旧样例读取，再在内存里连续执行两遍迁移；它演示转换幂等，不是在线数据库迁移服务。真实迁移仍需检查点、备份、兼容读写及恢复方案。

## 完整运行

```console
python -m ontology_lab demo --workdir .runs/my-capstone
```

目录必须是新目录。依次检查 `demo-report.json`：单位转换为 72 C；预期推理为真；有效与错误数据分别通过和拒绝；程序文档正确；响应丢失后对账成功且草稿数为 1；评估与迁移结果符合预期。

完整案例使用规则基线，不会自动调用第 07 课的真实模型，也不会将之前单独生成的结果自动送入动作服务。这使默认案例具有可重复行为。扩展时应显式传递经过验证的建议，并重新验证批准与动作边界。

## 交付一页说明

完成课程后，写出你的任务、使用者、输入数据、概念关系、正常结果、失败结果、指标、未实现项和下一步验证。记录实际运行环境、源码版本、数据版本及结果目录。

至少回答：为何需要本体；哪些行为由查询完成；哪些由逻辑推理完成；哪里调用了模型；谁批准动作；如何确认外部结果。若某项没有实际发生，应如实写明。

## 常见失败

将应用回滚等同于撤销外部工单，是恢复设计中的错误。迁移后忘记重建派生图、索引或缓存，也可能继续返回旧语义。只验证文件能解析，不足以说明关键能力问题仍成立。

## 结课练习

加入一种新观测，例如振动值。先定义单位、时效、设备关系和能力问题，再决定是否扩展建议合同与动作前提。至少准备正常、缺失、单位未知、过期与越权五种样本。

在结果说明中保留原温度实验与新增振动实验的分界，不把未测功能写成已实现。若新增模型诊断或真实写入，应另行建立领域审核与完整评估。
